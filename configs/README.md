# configs/ — TypeScript と Python が共有する唯一の真実

このディレクトリの JSON は **Worker (TypeScript) と 研究ラボ (Python) の両方が読む**。
同じ数字を 2 箇所に書かないための場所であって、それ以外の目的では使わない。

## なぜ YAML でも TOML でもなく JSON か

| 候補 | TS から読む | Python から読む | 判定 |
|---|---|---|---|
| YAML | 依存が要る | 依存が要る (PyYAML) | 両方で依存が増える |
| TOML | 依存が要る | 標準ライブラリ (`tomllib`) | TS 側が負ける |
| **JSON** | **標準** | **標準 (`json`)** | **これ** |

無料・低依存を最優先する方針 (RESEARCH_PROTOCOL.md 参照) では、
「設定ファイルを読むためだけにライブラリを 1 つ増やす」のは割に合わない。
コメントが書けない不便は、`_note` / `_why` フィールドを置くことで代替する
(パーサは無視するが、人間は読める)。

## universe.jp.json に銘柄リストを書かない理由

**銘柄リストをハードコードすると、その瞬間に生存者バイアスが入る。**

「2026 年に上場している銘柄」で 2015 年からバックテストすると、
2016-2025 年に上場廃止・経営破綻した銘柄が最初から存在しないことになる。
これはリターンを構造的に押し上げる。しかも押し上げ幅は戦略によって違うので、
「一律に何 % 割り引く」といった補正もできない。

そこでユニバースは **その時点の上場銘柄マスターから、ルールで毎日組み直す**。
`universe.jp.json` が持つのは「どう絞るか」であって「何を買うか」ではない。

上場廃止銘柄を含む銘柄マスターが手に入らない構成 (例: 現在の上場銘柄しか返さない
データソースしか無い場合) では、ラボは実行を止めずに
`survivorship_bias: "PRESENT"` を結果メタデータに刻む。
バイアスがあること自体より、あるのに黙っていることのほうが有害なため。

## qaiz_universe.json の再生成

```bash
npm run export:universe    # src/config/universe.ts → configs/qaiz_universe.json
```

CI がこのファイルの再生成結果と差分が無いことを検査する
(`npm test` の `universe-export` テスト)。TS 側でユニバースを編集して
JSON を更新し忘れると落ちる。
